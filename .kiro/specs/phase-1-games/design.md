# Design Document — Phase 1 Games

## Overview

Phase 1 Games adds four ephemeral slash command mini-games to pengmin-bot: `/trivia`, `/rps`, `/wordscramble`, and `/coinflip`. All game state lives in closure variables — no database writes, no leaderboards. Each command is a single file in `src/commands/fun/` that auto-loads via the existing `commandHandler.js` pattern.

A shared helper module, `src/commands/fun/gameUtils.js`, provides the common infrastructure all four games depend on: duplicate-session prevention, the AI commentary wrapper, the PvP invitation flow, and reusable embed/button builders. This keeps individual command files focused on game logic only.

The Endministrator persona (or whichever persona is active for the guild) narrates every result with a short in-character line generated by OpenAI. If the AI call fails, a static fallback string is used so the game result is always delivered.

---

## Architecture

```
src/commands/fun/
├── gameUtils.js          ← shared helpers (activeGames, commentary, PvP flow, embed builders)
├── trivia.js             ← /trivia command
├── rps.js                ← /rps command
├── wordscramble.js       ← /wordscramble command
└── coinflip.js           ← /coinflip command
```

### Dependency Graph

```
trivia.js ──────┐
rps.js ─────────┤──► gameUtils.js ──► aiService.js
wordscramble.js ─┤                ──► personaManager.js
coinflip.js ────┘                ──► prompts.js
```

Each game command:
1. Calls `gameUtils.checkAndLock(channelId)` — rejects duplicate sessions.
2. Calls `gameUtils.generateCommentary(persona, context, prompt)` — wraps `aiService.chat()` with fallback.
3. Calls `gameUtils.awaitOpponentAccept(interaction, challenger, opponent)` in PvP mode.
4. Uses `gameUtils` embed/button builders for consistent Discord UI.
5. Always calls `gameUtils.unlock(channelId)` in a `finally` block or collector `end` handler.

### Session Lifecycle

```
/game invoked
     │
     ▼
checkAndLock(channelId)
     │ already locked? → ephemeral error, return
     │
     ▼
[PvP only] awaitOpponentAccept()
     │ decline/timeout? → unlock(), return
     │
     ▼
game loop (collectors, buttons)
     │
     ▼
cleanupSession()   ← disables buttons, sends result embed, calls unlock()
```

## Components and Interfaces

### `gameUtils.js`

The module-level `activeGames` Set is the single source of truth for which channels have a live session.

```js
// Session management
checkAndLock(channelId)      → boolean  // false = channel already locked
unlock(channelId)            → void

// AI commentary
generateCommentary(persona, context, prompt)  → Promise<string>
// context: { persona: string, systemPrompt: string }
// prompt: ≤ 200-char game-result description
// Falls back to static string on any error

// PvP invitation
awaitOpponentAccept(interaction, challengerId, opponentId)
  → Promise<'accepted' | 'declined' | 'timeout'>

// Embed builders
buildGameEmbed(opts)         → EmbedBuilder
buildInviteEmbed(challenger, opponent, gameName)  → EmbedBuilder
buildResultEmbed(opts)       → EmbedBuilder

// Button builders
buildChoiceRow(choices)      → ActionRowBuilder
// choices: [{ label, emoji, customId }]
buildDisabledRow(row)        → ActionRowBuilder  // disables all buttons on an existing row

// Button customId helper
makeButtonId(gameTag, sessionId, action)  → string
// e.g. "rps:abc123:rock"
```

**`generateCommentary` signature in detail:**

```js
async function generateCommentary(persona, context, prompt) {
  // persona: { name, persona, context } from getActivePersona()
  // context: short string describing game state, max 200 chars (enforced internally)
  // prompt: instruction to the narrator, e.g. "Player won trivia. Topic: science."
  const systemPrompt = buildSystemPrompt({ persona: persona.persona, context: persona.context });
  const messages = [{ role: 'user', content: prompt.slice(0, 200) }];
  try {
    return await aiService.chat(messages, systemPrompt);
  } catch {
    return FALLBACK_MESSAGES[persona.name] ?? FALLBACK_MESSAGES.default;
  }
}
```

**`awaitOpponentAccept` signature in detail:**

```js
async function awaitOpponentAccept(interaction, challengerId, opponentId) {
  // Sends invite embed with Accept/Decline buttons
  // Collector filter: only opponentId can interact
  // Timeout: 60 000 ms
  // Returns 'accepted' | 'declined' | 'timeout'
  // Always disables buttons when the collector ends
}
```

### Individual Command Files

Each game file exports `{ data, execute }` following the existing bot convention:

```js
module.exports = {
  data: new SlashCommandBuilder()
    .setName('rps')
    .setDescription('...')
    .addStringOption(opt =>
      opt.setName('mode').addChoices(
        { name: 'PvAI', value: 'pvai' },
        { name: 'PvP',  value: 'pvp'  }
      )
    )
    .addUserOption(opt => opt.setName('opponent').setRequired(false)),

  async execute(interaction) {
    // guild-only guard
    // duplicate session guard (checkAndLock)
    // defer reply
    // resolve persona
    // [pvp] awaitOpponentAccept
    // game loop
    // cleanupSession (in finally)
  }
};
```

## Data Models

All state is held in closure variables within `execute()`. There is no serialization and no DB schema.

### Shared Session Context (conceptual, not a class)

```
sessionId     : string       — nanoid-style random ID, used in button customIds
channelId     : string       — Discord channel snowflake; key in activeGames
challengerId  : string       — Discord user snowflake
opponentId    : string|null  — Discord user snowflake (PvP only)
mode          : 'pvai'|'pvp'
persona       : { name, persona, context }
```

### Per-Game State

**Trivia**
```
question   : string
options    : { A, B, C, D }   — from AI parse
answer     : 'A'|'B'|'C'|'D'
pickedBy   : Map<userId, 'A'|'B'|'C'|'D'>
```

**RPS**
```
pickMap    : Map<userId, 'rock'|'paper'|'scissors'>
botMove    : 'rock'|'paper'|'scissors'|null
```

**WordScramble**
```
word       : string
scrambled  : string
hint       : string
hintUsed   : boolean
```

**CoinFlip**
```
pickMap    : Map<userId, 'heads'|'tails'>
flipResult : 'heads'|'tails'|null
```

### Button `customId` Format

```
<gameTag>:<sessionId>:<action>

Examples:
  rps:abc123:rock
  trivia:xyz789:B
  coinflip:def456:heads
  invite:ghi012:accept
```

The `sessionId` namespaces buttons so interactions from a previous session in the same channel cannot affect a new session.

### AI Response Parse Contracts

**Trivia** — AI is prompted to return valid JSON:
```json
{
  "question": "...",
  "options": { "A": "...", "B": "...", "C": "...", "D": "..." },
  "answer": "A"
}
```

**WordScramble** — AI is prompted to return valid JSON:
```json
{
  "word": "...",
  "scrambled": "...",
  "hint": "..."
}
```

If `JSON.parse` fails for either, the command replies with an ephemeral error and does not start a session.

## Correctness Properties

*A property is a characteristic or behavior that should hold true across all valid executions of a system — essentially, a formal statement about what the system should do. Properties serve as the bridge between human-readable specifications and machine-verifiable correctness guarantees.*

### Property 1: Duplicate Session Rejection

*For any* channel ID that is already present in `activeGames`, calling `checkAndLock` on that channel must return `false` and must not add a duplicate entry or change the set size.

**Validates: Requirements 1.1**

---

### Property 2: Session Cleanup Round-Trip

*For any* channel ID added to `activeGames`, after the session ends via any code path (win, loss, draw, timeout, or thrown error), the channel ID must no longer be present in `activeGames`.

**Validates: Requirements 1.2, 7.1**

---

### Property 3: AI Commentary Fallback Completeness

*For any* error thrown by `aiService.chat()`, `generateCommentary` must return a non-empty string — the game result must always be deliverable regardless of AI availability.

**Validates: Requirements 1.5**

---

### Property 4: Commentary Context Length Limit

*For any* game-result description string passed to `generateCommentary`, the prompt forwarded to `aiService.chat()` must be at most 200 characters long.

**Validates: Requirements 7.5**

---

### Property 5: Invitation Button Authorship Filter

*For any* user ID that is not the designated Opponent, the `InteractionCollector` filter inside `awaitOpponentAccept` must reject that interaction (return `false`), ensuring only the Opponent can accept or decline.

**Validates: Requirements 2.6**

---

### Property 6: Trivia AI Response Parser Completeness

*For any* string that is a valid JSON trivia response (containing `question`, `options.A`–`options.D`, and `answer`), the parser must return an object with all five fields present and non-empty, with `answer` being one of `A`, `B`, `C`, `D`.

**Validates: Requirements 3.2**

---

### Property 7: RPS Outcome Determinism

*For any* combination of player move and bot move (rock/paper/scissors × rock/paper/scissors = 9 pairs), the `resolveRps(playerMove, botMove)` function must return exactly `'win'`, `'loss'`, or `'draw'` according to the standard RPS rules — no pair should produce an undefined or unexpected result.

**Validates: Requirements 4.4**

---

### Property 8: RPS Bot Move Uniformity

*For any* sufficiently large sample of `pickBotMove()` calls (≥ 1000), each of the three moves must appear with a frequency between 25% and 42%, confirming the uniform distribution requirement.

**Validates: Requirements 4.9**

---

### Property 9: WordScramble AI Response Parser Completeness

*For any* string that is a valid JSON wordscramble response (containing `word`, `scrambled`, `hint`), the parser must return an object with all three fields present and non-empty, and `scrambled` must be an anagram of `word` (same character multiset, ignoring case).

**Validates: Requirements 5.2**

---

### Property 10: Case-Insensitive Answer Matching

*For any* correct answer string and any capitalisation variant of that string (upper, lower, mixed), the `matchesAnswer(input, answer)` function must return `true`, ensuring players are not penalised for capitalisation.

**Validates: Requirements 5.5**

---

### Property 11: CoinFlip Winner Logic Completeness

*For any* combination of `(player1Pick, player2Pick, flipResult)` drawn from `{ heads, tails }³`, the `resolveCoinflip` function must return one of `'player1'`, `'player2'`, or `'draw'` and must satisfy: if both picks match the flip → draw; if neither matches → draw; if only one matches → that player wins.

**Validates: Requirements 6.6**

---

### Property 12: Cleanup Disables All Buttons

*For any* active game session embed and its associated `ActionRowBuilder`, calling `buildDisabledRow` on each row must produce rows where every `ButtonBuilder` component has `disabled: true` — no interactive component should remain enabled after session end.

**Validates: Requirements 1.7, 7.3**

## Error Handling

### Guild-Only Guard

Every command's `execute` function checks `interaction.guildId` as the first operation. If absent (DM context), it replies with an ephemeral error and returns immediately.

```js
if (!interaction.guildId) {
  return interaction.reply({ content: '`*This command requires a server context.*`', flags: 64 });
}
```

### Duplicate Session Guard

`checkAndLock` is called before `deferReply`. If the channel is locked, an ephemeral reply is sent (no defer needed) and `execute` returns.

### Self-Invitation Guard

PvP commands validate `challenger.id !== opponent.id` before calling `awaitOpponentAccept`. If equal, they reply with an ephemeral error and unlock.

### AI Generation Failure

Both `generateTriviaQuestion` and `generateWordScramble` return `null` on parse failure. The command checks for `null`, sends an ephemeral error, unlocks, and returns — no session is started.

### Unhandled Errors

Every `execute` function wraps its body in `try/catch`. The `catch` block:
1. Calls `unlock(channelId)`.
2. Attempts `interaction.followUp` or `interaction.reply` with an ephemeral in-character error.
3. Logs the error via `logger.error`.

### Late Button Interactions

The `interactionCreate` handler for game buttons checks if the corresponding session is still in `activeGames`. If not, it replies with an ephemeral `*This session has already ended.*` message.

Alternatively, each collector's `filter` function returns `false` for interactions that arrive after the collector has stopped — the `interactionCreate` handler on the component then fires a late-reply.

### Collector Timeout

All collectors use the `time` option. The `end` event with `reason === 'time'` triggers `cleanupSession`, which disables buttons, sends the timeout result embed with commentary, and unlocks the channel.

## Testing Strategy

### Overview

The feature uses a dual testing approach:
- **Unit / property tests** for pure logic functions extracted into `gameUtils.js` and per-game resolvers.
- **Integration / example tests** for Discord interaction wiring (deferReply ordering, embed content, collector setup).

Since the games contain meaningful pure logic (RPS resolution, coinflip winner logic, case-insensitive matching, AI response parsers, activeGames lifecycle), property-based testing is appropriate for those layers. Discord API interaction wiring is tested with example-based unit tests using mock interactions.

### Property-Based Testing

Library: **[fast-check](https://github.com/dubzzz/fast-check)** (JavaScript/Node.js; no transpilation needed).

Configuration: minimum **100 iterations** per property test.

Each property test references its design property using a comment tag:
```js
// Feature: phase-1-games, Property N: <property_text>
```

**Properties to implement as PBT tests:**

| Property | Function Under Test | Generator |
|---|---|---|
| 1 — Duplicate session rejection | `checkAndLock` | arbitrary string (channel IDs) |
| 2 — Session cleanup round-trip | `checkAndLock` / `unlock` | arbitrary string + one of [win/loss/draw/timeout/error] |
| 3 — AI commentary fallback | `generateCommentary` (mocked aiService) | arbitrary Error objects |
| 4 — Commentary 200-char limit | `generateCommentary` | arbitrary strings of varying length |
| 5 — Invitation button filter | collector filter function | arbitrary userId strings |
| 6 — Trivia parser completeness | `parseTriviaResponse` | generated valid JSON trivia strings |
| 7 — RPS outcome determinism | `resolveRps` | fc.tuple(fc.constantFrom('rock','paper','scissors'), fc.constantFrom('rock','paper','scissors')) |
| 8 — RPS bot move uniformity | `pickBotMove` | fc.integer (seed) over 1000 samples |
| 9 — WordScramble parser completeness | `parseWordScrambleResponse` | generated valid JSON scramble strings |
| 10 — Case-insensitive matching | `matchesAnswer` | fc.tuple(fc.string, fc.string) with case transformations |
| 11 — Coinflip winner logic | `resolveCoinflip` | fc.tuple(fc.constantFrom('heads','tails'), fc.constantFrom('heads','tails'), fc.constantFrom('heads','tails')) |
| 12 — Cleanup disables buttons | `buildDisabledRow` | generated ActionRows with random button counts 1–5 |

### Unit / Example Tests

- Verify `deferReply` is called before any `await` on async work (mock interaction).
- Verify invitation embed contains exactly two buttons (Accept, Decline).
- Verify PvP collector filter rejects non-opponent users (specific example).
- Verify self-invitation produces an ephemeral rejection and no session lock.
- Verify AI failure produces non-empty fallback in each game.
- Verify button `customId` format matches `<game>:<sessionId>:<action>` pattern.
- Verify DM invocations are rejected before any async work.
