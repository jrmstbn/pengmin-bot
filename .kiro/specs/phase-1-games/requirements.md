# Requirements Document

## Introduction

Phase 1 Games adds four ephemeral mini-games to pengmin-bot: `/trivia`, `/rps` (Rock Paper Scissors), `/wordscramble`, and `/coinflip`. All games are stateless — no database writes, no leaderboards. Game state lives entirely in the interaction closure.

Every game supports two play modes: **PvAI** (one human vs the AI) and **PvP** (two human players). In both modes the active guild persona (Endministrator by default) acts as a narrator and judge, delivering in-character commentary on outcomes via OpenAI. Rich Discord UI is used throughout: embeds for game state, buttons for choices, message collectors for text input.

The four games drop as individual files into `src/commands/fun/` and are auto-loaded with no other changes required.

---

## Glossary

- **Bot**: The pengmin-bot Discord application (Endministrator persona).
- **Game_Engine**: The per-command module that manages a single game session (state, UI, timing).
- **Persona_Narrator**: The AI commentary layer — calls `aiService.chat()` with the active guild persona to produce in-character result messages.
- **Active_Persona**: The persona resolved by `getActivePersona(guildId)` for the current guild; defaults to Endministrator.
- **PvAI_Mode**: A single human player competing against the Bot.
- **PvP_Mode**: Two human players competing against each other, with the Bot as observer/narrator.
- **Challenger**: The user who invoked the slash command.
- **Opponent**: The second human player in PvP_Mode, invited by the Challenger.
- **Interaction_Collector**: A `discord.js` `InteractionCollector` that awaits button presses.
- **Message_Collector**: A `discord.js` `MessageCollector` that awaits text input.
- **Session**: A single in-progress game instance, keyed by channel ID in an `activeGames` Set.
- **Embed**: A `discord.js` `EmbedBuilder` object rendered in the Discord client.
- **ActionRow**: A `discord.js` `ActionRowBuilder` containing `ButtonBuilder` components.
- **AI_Commentary**: A short in-character text response generated by `Persona_Narrator`.
- **Timeout**: The maximum wall-clock duration allowed for a player action before the game ends.

## Requirements

### Requirement 1: Shared Game Infrastructure

**User Story:** As a developer, I want a shared set of conventions for all Phase 1 games, so that each game command behaves consistently and is easy to maintain.

#### Acceptance Criteria

1. THE Game_Engine SHALL prevent duplicate sessions by maintaining a per-channel `activeGames` Set and rejecting a second invocation in the same channel with an ephemeral error reply.
2. WHEN a Session ends for any reason (win, loss, draw, timeout, error), THE Game_Engine SHALL remove the channel ID from `activeGames`; IF the removal fails due to a transient error, THE Game_Engine SHALL retry the cleanup operation until the channel is unlocked.
3. THE Game_Engine SHALL resolve the Active_Persona for the guild using `getActivePersona(guildId)` before generating any AI_Commentary.
4. THE Persona_Narrator SHALL produce AI_Commentary by calling `aiService.chat()` with a concise game-result prompt and the Active_Persona's system prompt built via `prompts.buildSystemPrompt()`.
5. IF the AI_Commentary call fails, THEN THE Persona_Narrator SHALL fall back to a static in-character message so the game result is still delivered.
6. THE Game_Engine SHALL defer the initial interaction with `interaction.deferReply()` before performing any async work that may exceed Discord's 3-second acknowledgement window.
7. WHEN a Session requires cleanup for any reason (timeout, forfeit, error, or normal end), THE Game_Engine SHALL disable all buttons on the game Embed, send an appropriate end message with AI_Commentary, and remove the channel from `activeGames`.
8. THE Game_Engine SHALL accept a `mode` slash command option with values `pvai` (default) and `pvp` on every game command that supports PvP_Mode.

### Requirement 2: PvP Mode — Opponent Invitation Flow

**User Story:** As a Challenger, I want to invite another server member to play against me, so that I can compete with a friend in real time.

#### Acceptance Criteria

1. WHEN `mode` is `pvp`, THE Game_Engine SHALL accept a required `opponent` user option naming the Opponent Discord member.
2. WHEN a PvP_Mode game is initiated, THE Game_Engine SHALL send an invitation Embed to the channel mentioning the Opponent and including an **Accept** and **Decline** button.
3. WHEN the Opponent clicks **Accept**, THE Game_Engine SHALL start the game and present both players with their respective input UI.
4. WHEN the Opponent clicks **Decline**, THE Game_Engine SHALL end the Session and send an AI_Commentary message acknowledging the refusal in-character.
5. IF the Opponent does not respond to the invitation within 60 seconds, THEN THE Game_Engine SHALL end the Session with a Timeout message.
6. THE Game_Engine SHALL restrict the invitation buttons so only the Opponent can interact with them; these buttons SHALL remain restricted after the Session ends so that no further interactions can be submitted.
7. IF the Challenger invites themselves as Opponent, THEN THE Game_Engine SHALL reject the command with an ephemeral error and not start a Session; IF a self-invitation somehow bypasses the initial check, THE Game_Engine SHALL perform a secondary validation before starting and abort the Session if Challenger and Opponent share the same user ID.

### Requirement 3: /trivia Command

**User Story:** As a user, I want to be quizzed on a topic of my choice by the Bot, so that I can test my knowledge and receive an in-character verdict.

#### Acceptance Criteria

1. THE Trivia_Command SHALL register a slash command named `trivia` with a required string option `topic` and an optional string option `mode` (`pvai` default, `pvp`).
2. WHEN the command is invoked, THE Persona_Narrator SHALL call the AI to generate a question, four distinct answer options labelled A–D, and the correct answer letter — all in a single AI call.
3. THE Trivia_Command SHALL render the question and four answer options in an Embed with four buttons labelled **A**, **B**, **C**, **D**.
4. WHILE a PvAI_Mode trivia Session is active, THE Trivia_Command SHALL collect exactly one button press from the Challenger within 30 seconds.
5. WHILE a PvP_Mode trivia Session is active, THE Trivia_Command SHALL collect one button press from each player independently within 30 seconds.
6. WHEN the Challenger (PvAI) selects an answer, THE Trivia_Command SHALL disable all buttons, then call THE Persona_Narrator to reveal whether the answer is correct and deliver a verdict Embed with AI_Commentary.
7. WHEN both players respond in PvP_Mode, THE Trivia_Command SHALL reveal both answers simultaneously, declare the winner (or draw), and deliver a verdict Embed with AI_Commentary; THE Trivia_Command SHALL only apply PvP verdict logic when a PvP_Mode Session is active.
8. IF only one player responds within the Timeout in PvP_Mode, THEN THE Trivia_Command SHALL award the win to the responding player and include this in the AI_Commentary.
9. IF neither player responds within the Timeout in PvP_Mode, THEN THE Trivia_Command SHALL declare a draw and end the Session.
10. IF the AI fails to generate a valid question, THEN THE Trivia_Command SHALL reply with an ephemeral error message and not start a Session.

### Requirement 4: /rps Command

**User Story:** As a user, I want to play Rock Paper Scissors against the Bot or another player, so that I can enjoy a quick match with in-character commentary.

#### Acceptance Criteria

1. THE RPS_Command SHALL register a slash command named `rps` with an optional string option `mode` (`pvai` default, `pvp`).
2. THE RPS_Command SHALL render an Embed with three buttons: 🪨 **Rock**, 📄 **Paper**, ✂️ **Scissors**.
3. WHILE a PvAI_Mode RPS Session is active, THE RPS_Command SHALL collect exactly one button press from the Challenger within 30 seconds.
4. WHEN the Challenger picks in PvAI_Mode, THE RPS_Command SHALL select a random move for the Bot, resolve the outcome (win / lose / draw), edit the Embed to show both choices and the result, and append AI_Commentary.
5. WHILE a PvP_Mode RPS Session is active, THE RPS_Command SHALL collect one button press from each player independently within 30 seconds using two separate Interaction_Collectors.
6. THE RPS_Command SHALL display a waiting Embed to each player that does not reveal the other player's choice until both have picked.
7. WHEN both players have picked in PvP_Mode, THE RPS_Command SHALL resolve the outcome, edit the Embed to show both choices and the result, and append AI_Commentary.
8. IF only one player picks within the Timeout in PvP_Mode, THEN THE RPS_Command SHALL wait for the Timeout to expire before declaring the non-responding player as having forfeited, and SHALL include this in the AI_Commentary.
9. THE RPS_Command SHALL determine the AI Bot's move using `Math.random()` with equal probability (≈33.3%) for each option.

### Requirement 5: /wordscramble Command

**User Story:** As a user, I want to unscramble a word presented by the Bot, so that I can test my vocabulary and receive a cryptic hint if I'm stuck.

#### Acceptance Criteria

1. THE WordScramble_Command SHALL register a slash command named `wordscramble` with an optional string option `mode` (`pvai` default, `pvp`).
2. WHEN the command is invoked, THE Persona_Narrator SHALL call the AI to produce a word, a scrambled version of that word, and a cryptic hint — all in a single AI call.
3. THE WordScramble_Command SHALL render an Embed showing the scrambled word and a **Get Hint** button; the answer SHALL NOT be shown in the Embed.
4. WHILE a PvAI_Mode wordscramble Session is active, THE WordScramble_Command SHALL use a Message_Collector to accept text input from the Challenger within 60 seconds.
5. WHEN the Challenger types the correct answer (case-insensitive match), THE WordScramble_Command SHALL stop the collector, update the Embed to show the correct word, and deliver a win AI_Commentary.
6. WHEN the Challenger clicks **Get Hint**, THE WordScramble_Command SHALL reveal the AI-generated cryptic hint by editing the Embed; the hint button SHALL be disabled after use.
7. IF the Timeout fires before the Challenger answers, THEN THE WordScramble_Command SHALL reveal the correct word and deliver a loss AI_Commentary.
8. WHILE a PvP_Mode wordscramble Session is active, THE WordScramble_Command SHALL use two independent Message_Collectors, one per player, and award the win to the first player who submits the correct answer.
9. WHEN one player wins in PvP_Mode, THE WordScramble_Command SHALL stop both collectors, update the Embed to declare the winner, and deliver AI_Commentary.
10. IF the AI fails to generate a valid word and scramble, THEN THE WordScramble_Command SHALL reply with an ephemeral error and not start a Session.

### Requirement 6: /coinflip Command

**User Story:** As a user, I want to flip a coin and have the Bot deliver the result with a dry in-character one-liner, so that I can settle disputes or make quick decisions with flair.

#### Acceptance Criteria

1. THE CoinFlip_Command SHALL register a slash command named `coinflip` with an optional string option `mode` (`pvai` default, `pvp`).
2. THE CoinFlip_Command SHALL render an Embed presenting two buttons: **Heads** and **Tails**.
3. WHILE a PvAI_Mode coinflip Session is active, THE CoinFlip_Command SHALL collect exactly one button press from the Challenger within 30 seconds.
4. WHEN the Challenger picks in PvAI_Mode, THE CoinFlip_Command SHALL resolve the flip using `Math.random()` (50/50), edit the Embed to show the result, and append a one-line AI_Commentary.
5. WHILE a PvP_Mode coinflip Session is active, THE CoinFlip_Command SHALL collect one button press from each player independently; each player picks Heads or Tails.
6. WHEN both players have picked in PvP_Mode and the coin has been flipped, THE CoinFlip_Command SHALL evaluate winner logic only after both actions are complete, declaring the player(s) whose pick matches the flip result as winner(s); if both or neither match, the outcome is a draw.
7. WHEN the coinflip result is delivered, THE CoinFlip_Command SHALL disable all buttons and append AI_Commentary to the Embed.
8. IF the Timeout fires before a player picks, THE CoinFlip_Command SHALL flip the coin anyway, show the result, note who did not pick, and deliver AI_Commentary.

### Requirement 7: Error Handling and Edge Cases

**User Story:** As a server member, I want all game commands to handle unexpected situations gracefully, so that the bot never crashes or leaves a channel locked.

#### Acceptance Criteria

1. IF an unhandled error occurs inside any Game_Engine, THEN THE Game_Engine SHALL catch the error, remove the channel from `activeGames`, and reply with an ephemeral in-character error message.
2. WHEN a game command is used in a DM channel, THE Game_Engine SHALL reject the interaction with an ephemeral message stating the command requires a guild context.
3. THE Game_Engine SHALL disable all interactive components (buttons) when editing a final result Embed so that expired interactions cannot be submitted.
4. IF a button interaction is submitted after the collector has already ended, THEN THE Game_Engine SHALL reply to that interaction with an ephemeral "this game has already ended" message.
5. THE AI_Commentary prompt sent to `Persona_Narrator` SHALL be limited to a maximum of 200 characters of game-result context to avoid excessive token usage.
6. IF the Active_Persona cannot be resolved, THEN THE Persona_Narrator SHALL use the Endministrator disk-fallback persona without throwing an error.
